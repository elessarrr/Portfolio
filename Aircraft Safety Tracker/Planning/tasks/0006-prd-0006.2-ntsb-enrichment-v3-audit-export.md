## 1. Introduction/Overview

### Problem statement

PRD 0006.1 completed a full-corpus NTSB enrichment audit (3,710 Boeing/Airbus records → 3,649 viable unique → **679 working links**). The summary report (`data/logs/ntsb_enrichment_full_audit.json`) stores **counts** and **≤10 sample rows per bucket** — not the full row lists product needs to review before write-path import.

**Gap:** Product cannot inspect all 679 working-link candidates (or other buckets) without re-running a ~26-minute HTTP audit or raising `--sample` to an impractical size.

### Goal

Extend the audit CLI so a **single run** writes **every classified row** to **one common export file**, enabling product review and downstream import filtering without re-fetching NTSB URLs.

---

## 2. Goals

1. **Full row export:** Persist all audit-classified rows (not just samples) in one file.
2. **Review-ready:** Product can open/filter the export to inspect all 679 working-link rows before Task 6 write path.
3. **Count integrity:** Export line counts must match summary JSON bucket counts.
4. **No regression:** Existing summary report + sample buckets remain; export is additive.
5. **Reuse 0006.1 pipeline:** Dedupe, link viability, and unknown-aircraft rules unchanged.

---

## 3. User Stories

1. **As a** product owner,  
   **I want** a single file listing every NTSB candidate with working links,  
   **so that** I can review the full 679-row set before approving import.

2. **As a** product owner,  
   **I want** all audit buckets (deduped, working, broken, unknown-aircraft) in one export with a bucket label,  
   **so that** I can filter/sort without juggling multiple files.

3. **As a** developer,  
   **I want** rows streamed to disk during the audit pass,  
   **so that** we don't hold thousands of rows in memory and don't need a second HTTP run to regenerate lists.

### FR-10: Full audit row export (one common file) — **NEW**

1. **FR-10.1** `scripts/audit_ntsb_enrichment.py` must accept `--export-rows PATH` (NDJSON / JSON Lines).
2. **FR-10.2** When `--export-rows` is set, write **every classified row** to that **single file** as the audit runs (append/stream; do not buffer entire corpus in memory).
3. **FR-10.3** Each exported line is one JSON object with at minimum:
   - `bucket` — one of: `skipped_deduped_asn_covered`, `viable_with_working_link`, `viable_with_broken_link`, `unknown_aircraft_included` (when applicable; working/broken buckets take precedence after link check)
   - `source_record_id`, `date`, `make_model`, `operator`, `location`, `fatalities`
   - `ntsb_url`, `aircraft_id` (nullable), `unknown_aircraft` (bool)
   - `link_viable`, `link_reason` (when `--check-links` enabled)
   - `closest_asn_match` (object or null, when dedupe ran)
4. **FR-10.4** **One common file** for all buckets — not separate files per bucket. Consumers filter by `bucket` field.
5. **FR-10.5** Summary JSON (`--out`) retains counts + small samples (FR-7.3); export file holds the **complete** row lists.
6. **FR-10.6** After audit completes, validate: count of lines per `bucket` in export file equals corresponding count in summary JSON (fail loudly or log mismatch summary).
7. **FR-10.7** Default export path (when flag used without override): `data/logs/ntsb_enrichment_audit_rows.jsonl`.
8. **FR-10.8** Document re-run policy: if full HTTP link check is required again, `--export-rows` is written during that pass; optional future `--link-cache` is out of scope for 0006.2.

### FR-11: Review gate (moved from 0006.1 FR-7.4)

1. **FR-11.1** Product reviews **full export** (filter `bucket=viable_with_working_link`) — not samples alone.
2. **FR-11.2** Approve write-path import (PRD 0006.1 Task 6.0) only after export review.

### FR-12: CAROL empty-SPA viability + resolver docket fallback — **NEW (2026-05-31)**

*Incorporates QA click-through findings (`.gstack/qa-reports/qa-report-ntsb-working-link-field-check-2026-05-30.md`, Section H).*

1. **FR-12.1** `validate_ntsb_url()` must reject CAROL detail URLs (`carol.ntsb.gov/investigations/detail/{mkey}`) that return HTTP 200 with an empty React SPA shell (`<main id="root"></main>`, no investigation content markers). Reason code: `carol_empty_spa`.
2. **FR-12.2** `resolve_ntsb_source_url()` (and audit `--check-links` path) must validate CAROL first; when CAROL fails viability, **fall back to docket** (`data.ntsb.gov/Docket/?NTSBNumber=…`) and validate that candidate before accepting.
3. **FR-12.3** When both CAROL and docket fail, return no URL (`None`) — honest "no link" for import/UI (e.g. blank CAROL + unreleased docket).
4. **FR-12.4** Audit export rows must record `link_reason` from the last failed candidate when no viable URL is found (`carol_empty_spa`, `docket_not_released`, `no_viable_url`, etc.).
5. **FR-12.5** Re-run full-corpus audit with updated viability rules **before Step 4 (Task 6.0) import**; prior **679** working-link count is stale and will decrease (CAROL shells move to docket or broken).
6. **FR-12.6** Unit tests: empty CAROL SPA rejected; resolver falls back to viable docket; both dead → `None` + `docket_not_released`.

## 6. Design Considerations

- Export format: **JSONL** (one JSON object per line) for grep/jq/streaming.
- Product review workflow: `jq 'select(.bucket=="viable_with_working_link")' data/logs/ntsb_enrichment_audit_rows.jsonl`
- Keep summary JSON small for quick count checks; use export for row-level review.

---

## 7. Technical Considerations

### Pipeline (updated)

```text
NTSB JSON input
  → parse → dedupe vs ASN → viable unique set
  → resolve URL + viability check (CAROL → docket fallback per FR-12)
  → summary JSON (counts + samples)     ← existing (--out)
  → export JSONL (ALL rows, all buckets) ← NEW (--export-rows)
  → [REVIEW GATE — product approval on full working-link set]
  → write-path import (0006.1 Task 6.0)
```

### Example CLI

```bash
DATABASE_URL=sqlite:////absolute/path/to/data/aircraft_safety_v3.db \
PYTHONPATH=. python scripts/audit_ntsb_enrichment.py \
  --input data/raw/ntsb_records_full.json \
  --include-unknown-aircraft \
  --check-links \
  --out data/logs/ntsb_enrichment_full_audit.json \
  --export-rows data/logs/ntsb_enrichment_audit_rows.jsonl
```
