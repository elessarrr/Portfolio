## 1. Introduction / Overview

### Problem Statement

PRD 0007 imported **6,466 FAA AIDS** incidents with ASIAS URLs on **APEX page 12** (search form):

```
https://www.asias.faa.gov/apex/f?p=100:12:::NO::P12_AIDS_RPRT_NBR:{c5_id}
```

Product QA confirmed this is **not acceptable UX**: clicking “Details ↗” opens the AIDS Search form with the report number pre-filled; the user must click **Search AIDS** again to see the report.

The correct deep link opens the **brief report** on **APEX page 18**:

```
https://www.asias.faa.gov/apex/f?p=100:18:::NO::AP_BRIEF_RPT_VAR:{c5_id}
```

Example (product-verified): `19850309009149I` → direct factual narrative / brief report view.

PRD 0007.1 built HTTP viability auditing (including page-12 “working” checks). That proved **HTTP reachability**, not **product-ready links**. A merged page-12 audit showing 6,466/6,466 “working” still left users on the search form.

### Experiment Gate (completed)

A stratified sample of **200** records (seed 42) was audited in **brief** mode. After retry of transient failures (`fetch_error`, `asias_cdn_error`):

| Metric | Result |
|--------|--------|
| Sample size | 200 |
| `working_brief_report` | **200 / 200 (100%)** |
| `not_working` after retry | 0 |

This meets the product gate of **≥90%** `working_brief_report` before full-corpus migration.

### Goal

1. **Rewrite** all ~6,466 `IncidentSource.source_url` values for `FAA_AIDS` from page 12 → page 18 where the brief URL is audit-verified.
2. **Default new imports** to page 18 so the problem does not regress.
3. **Preserve provenance:** no hard-deletes; optional `is_active` soft-delete only for rows that fail brief-mode audit after migration.

## 2. Goals

1. **Product-ready links:** Every active FAA AIDS `source_url` opens the brief report without an extra “Search AIDS” click.
2. **Full-corpus brief audit:** Dry-run audit of all 6,466 page-18 URLs with three-tier buckets; retry transient `not_working` rows before migration.
3. **Gated migration:** DB `source_url` updates only for `source_record_id`s with `bucket = working_brief_report` in the approved audit JSONL (`--require-audit`).
4. **Importer alignment:** `FAAAIDSImporter` uses `build_faa_aids_brief_report_url()` (or equivalent) at import time.
5. **No regression on outage safety:** Full brief audit aborts when ASIAS homepage is not HTTP 2xx (same liveness guard as 0007.1).
6. **Documented rollout:** JOURNAL + LEARNINGS updated; `/audit-urls` skill FAA section reflects post-migration workflow.

## 3. User Stories

1. **As a** portfolio visitor,  
   **I want** clicking “Details ↗” on a FAA AIDS incident to open the official brief report immediately,  
   **so that** I don’t have to interact with the ASIAS search form.

2. **As a** product owner,  
   **I want** full-corpus brief URL validation before any DB URL rewrite,  
   **so that** we don’t point thousands of users at broken or wrong pages.

3. **As a** developer,  
   **I want** migration tied to an audit export (`--require-audit`),  
   **so that** only verified IDs are updated and flakes are retried first.

4. **As a** developer,  
   **I want** the importer to emit page-18 URLs by default,  
   **so that** re-imports and new rows don’t reintroduce page-12 links.

5. **As a** product owner,  
   **I want** a short manual browser spot-check after migration,  
   **so that** we confirm real-browser UX matches automated classification.

## 4. Functional Requirements

### FR-1: URL builders (existing — verify / document)

**File:** `app/ingestion/url_builders/faa_aids.py`

1. **FR-1.1** `build_faa_aids_brief_report_url(source_record_id)` returns page-18 URL with `AP_BRIEF_RPT_VAR:{id}`.
2. **FR-1.2** `build_faa_aids_search_url(source_record_id)` remains available for legacy / comparison audits only.
3. **FR-1.3** `build_faa_aids_url()` **must** be updated to call `build_faa_aids_brief_report_url()` (breaking change from page-12 default documented in PRD 0007).

### FR-2: Three-tier audit buckets (implemented in 0007.1+ tooling)

**File:** `app/ingestion/url_builders/faa_aids_viability.py`

| `bucket` | Meaning |
|----------|---------|
| `working_brief_report` | User lands on brief report (product OK) |
| `working_search_prefill` | HTTP OK but search/intermediate page |
| `not_working` | CDN error, timeout, 404, empty APEX, etc. |

1. **FR-2.1** Brief-mode classification uses body heuristics (`ap_brief`, `factual narrative`, vs `search aids`, `p12_aids_rprt_nbr`).
2. **FR-2.2** Search-mode classification is **strict**: page-12 URLs with only generic markers → `working_search_prefill`, not `working_brief_report`.
3. **FR-2.3** `validate_faa_aids_url_extended(..., url_mode="brief"|"search")` returns `product_viable = (bucket == working_brief_report)`.

### FR-3: Full-corpus brief audit (dry-run first)

**File:** `scripts/audit_faa_aids_urls.py`

1. **FR-3.1** Run with `--url-mode brief` (default) against all 6,466 rows (input: `faa_aids_enrichment_final_import_01Jun2026.jsonl` or DB-derived list).
2. **FR-3.2** **First run must use `--dry-run`** — no DB `is_active` or `source_url` changes.
3. **FR-3.3** Performance defaults: `--concurrency 16`, `--timeout 15`, jitter on, `retry_once` on transient errors (see `/audit-urls` skill).
4. **FR-3.4** Call `probe_asias_liveness()` before bulk check; exit code 2 if ASIAS globally down — **no writes**.
5. **FR-3.5** Export: `data/logs/faa_aids_url_audit_brief_{YYYY-MM-DD}.jsonl` with fields including `bucket`, `product_viable`, `url_mode`, `faa_aids_url` (page-18 URL checked).
6. **FR-3.6** Summary: `data/logs/faa_aids_url_audit_summary.json` (or dated variant) with `bucket_counts` and `product_viable_count`.

### FR-4: Retry transient failures

1. **FR-4.1** Re-run failed rows only:
   ```bash
   PYTHONPATH=. python scripts/audit_faa_aids_urls.py \
     --retry-failures-from data/logs/faa_aids_url_audit_brief_{date}.jsonl \
     --merge-into data/logs/faa_aids_url_audit_brief_{date}.jsonl \
     --url-mode brief --dry-run
   ```
2. **FR-4.2** Merged output must use `{stem}_merged.jsonl` when merge target equals retry source (bug fix — do not overwrite unrelated `faa_aids_url_audit_merged_{date}.jsonl` from page-12 era).
3. **FR-4.3** Repeat retry until `not_working` is reviewed or accepted as genuinely broken records.

### FR-5: Review gate (product)

1. **FR-5.1** Product reviews `not_working` bucket and reason breakdown (`asias_cdn_error`, `asias_backend_timeout`, `asias_record_not_found`, etc.).
2. **FR-5.2** **Gate to proceed:** `product_viable_count / 6466 ≥ 0.90` on merged brief audit (sample already achieved 100%).
3. **FR-5.3** **Manual spot-check:** Product opens **5–10** brief URLs in a real browser (mix of years, Boeing/Airbus, operators) from the audit export or experiment file.

### FR-6: DB migration — `source_url` rewrite

**File:** `scripts/migrate_faa_aids_urls_to_brief.py`

1. **FR-6.1** Default mode is **dry-run**; `--apply` required for DB writes.
2. **FR-6.2** For each `IncidentSource` where `source_name = 'FAA_AIDS'`, set `source_url = build_faa_aids_brief_report_url(source_record_id)`.
3. **FR-6.3** With `--require-audit PATH`, only migrate rows whose `source_record_id` appears in the audit JSONL with `bucket = working_brief_report`.
4. **FR-6.4** Skip rows already on page 18 (`:18:` + `AP_BRIEF_RPT_VAR` in URL).
5. **FR-6.5** Write migration report: `data/logs/faa_aids_url_migration_to_brief.jsonl` (actions: `would_migrate`, `migrate`, `skip_audit_gate`, `already_brief`).
6. **FR-6.6** Batch commit; update `last_updated` on changed rows.

### FR-7: Importer default URL

**File:** `app/ingestion/importers/faa_aids_importer.py`

1. **FR-7.1** At import time, set `source_url` via `build_faa_aids_brief_report_url(c5)` (not search URL).
2. **FR-7.2** Existing rows updated by FR-6; re-import of same `source_record_id` must be idempotent (upsert overwrites with brief URL).

### FR-8: Optional — `is_active` write-back (brief mode)

**Only if product wants to hide true failures after brief audit.**

1. **FR-8.1** Run `audit_faa_aids_urls.py --url-mode brief` **without** `--dry-run`.
2. **FR-8.2** In brief mode, `db_should_remain_active()` sets `is_active = True` only for `working_brief_report`; `working_search_prefill` and `not_working` → `False`.
3. **FR-8.3** This is **optional** and separate from URL migration; product may migrate URLs first and defer `is_active` cleanup.

### FR-9: Post-migration validation

1. **FR-9.1** Re-run brief audit (dry-run) on a sample or full set and confirm `product_viable` rate unchanged or improved.
2. **FR-9.2** `scripts/smoke_faa_aids_ui.py` — verify app renders FAA links (shape only; not live ASIAS).
3. **FR-9.3** Manual: click 5–10 “Details ↗” on aircraft pages in dev/staging — confirm brief report loads.

### FR-10: Tests

1. **FR-10.1** Existing `tests/test_faa_aids_viability.py` covers buckets and brief/search modes.
2. **FR-10.2** Add or extend tests for `migrate_faa_aids_urls_to_brief.py` dry-run logic (`--require-audit` gate) if not present.
3. **FR-10.3** Update `tests/test_faa_aids_url_builder.py` if `build_faa_aids_url()` default changes to brief.

7. **No NTSB URL changes** — FAA AIDS only.

## 7. Technical Considerations

### Pipeline (recommended order)

```
[0] ASIAS liveness OK (`probe_asias_liveness()` or `faa_brief_retry4_watch_state.json`)
  ↓
[1] audit_faa_aids_urls.py --url-mode brief --dry-run  (6,466 rows)
  ↓
[2] Retry not_working + merge → faa_aids_url_audit_brief_{date}_merged.jsonl
  ↓
[3] Product review gate (≥90% working_brief_report + manual 5–10 URLs)
  ↓
[4] migrate_faa_aids_urls_to_brief.py --apply --require-audit <merged jsonl>
  ↓
[5] faa_aids_importer.py → brief URL default (FR-7)
  ↓
[6] Optional: brief audit without --dry-run for is_active (FR-8)
  ↓
[7] Post-migration smoke + manual QA (FR-9)
```

### Estimated runtime

| Step | Estimate |
|------|----------|
| Full brief dry-run (6,466, concurrency 16, jitter) | ~45–70 min |
| Retry flakes | Minutes (typically &lt;100 rows) |
| Migration `--apply` | &lt;1 min DB |

Run during ASIAS stable hours; optional 30-min cron via `scripts/run_faa_brief_retry4_when_live.sh` to auto-start retries when the portal is up.


### Known operational hazards

1. **Merge path collision:** Never use `--merge-into` equal to `--retry-failures-from` without `{stem}_merged.jsonl` sidecar naming — avoids overwriting legacy page-12 merged exports.
2. **Transient flakes:** `fetch_error` / `asias_cdn_error` on first pass often clear on retry (observed: 60/60 sample recovered).
3. **Logs not in git:** Audit JSONL lives under `data/logs/` — back up before destructive merges.
