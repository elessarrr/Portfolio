## 1. Introduction / Overview

### Problem Statement

PRD 0007 imported **6,466 FAA AIDS incidents** with ASIAS portal URLs of the form:

```
https://www.asias.faa.gov/apex/f?p=100:12:::NO::P12_AIDS_RPRT_NBR:{c5_id}
```

A product review of the import log revealed that **individual URLs return Akamai CDN errors** (HTTP reference `#102.d0e9c717.1780310489.9ae7f7d1` via `errors.edgesuite.net`) rather than the expected ASIAS report page. The ASIAS portal returns **HTTP 503** for individual record lookups (confirmed in `scripts/smoke_faa_aids_ui.py` results), and the CDN error page is rendered for end-users clicking the link.

This is the same class of problem as PRD 0006.2 §FR-12 (CAROL empty-SPA shells), where a URL that technically responds with HTTP 200 or a redirect is not actually a viable link for users.

### ASIAS-Specific Failure Modes

From investigation of the error screenshot and HTTP smoke results:

| Pattern | Symptom | Classification |
|---------|---------|----------------|
| Akamai CDN error page | HTTP 503 + `errors.edgesuite.net` reference in body | `asias_cdn_error` |
| Backend timeout / overload | HTTP 504 | `asias_backend_timeout` |
| Record not found | HTTP 404 (APEX redirect may show 200 with "no data" body) | `asias_record_not_found` |
| APEX "no data" page | HTTP 200 but body contains "No data found" / empty report table | `asias_empty_report` |
| Working record | HTTP 200 + report content markers (date, report number, aircraft type) | `working` |

### Complication: Global vs. Per-Record Failures

ASIAS (`www.asias.faa.gov`) is intermittently unavailable at a **global** level (the whole portal may 503 during off-hours or under load). Marking all 6,466 records dead during a global outage would be wrong.

**Solution (mirrors NTSB pattern):** Before individual checks, issue a **site-liveness probe** on a known-stable ASIAS URL. If the probe fails, abort the audit run cleanly — do not mark any records as broken. Only proceed when the site is globally responsive.

### Goal

1. Check every imported FAA AIDS URL for viability.
2. Produce a **two-section JSONL** export: `working` and `not_working` (with reason codes).
3. **Update the DB:** soft-delete `IncidentSource` rows for broken links (`is_active = False`); keep `source_url` for provenance.
4. The aircraft page UI should no longer surface broken FAA links.

## 2. Goals

1. **Full URL verification:** Check all 6,466 FAA AIDS source URLs against ASIAS.
2. **Classified export:** Produce `data/logs/faa_aids_url_audit_{date}.jsonl` with every row classified as `working` or `not_working` + reason code.

5. **Repeatable / idempotent:** Re-run the audit at any time; re-running re-checks all rows (or optionally only `is_active=True` rows); applying cleanup twice produces the same DB state.
6. **Test coverage:** Unit tests for all ASIAS failure-mode classifiers and the global liveness guard.
7. **UI effect:** Aircraft pages with FAA AIDS sources will no longer show broken links after DB cleanup.

## 4. Functional Requirements

### FR-1: ASIAS URL Viability Module

**File:** `app/ingestion/url_builders/faa_aids_viability.py`  
(Mirrors `app/ingestion/url_builders/ntsb_viability.py`)

1. **FR-1.1** Implement `validate_faa_aids_url(url, *, fetcher, timeout) → (viable: bool, http_status: int | None, reason: str | None)`.
2. **FR-1.2** Return `viable=False, reason="asias_cdn_error"` when HTTP status is 503 or body contains `errors.edgesuite.net`.
3. **FR-1.3** Return `viable=False, reason="asias_backend_timeout"` when HTTP status is 504 or request times out.
4. **FR-1.4** Return `viable=False, reason="asias_record_not_found"` when HTTP status is 404.
5. **FR-1.5** Return `viable=False, reason="asias_empty_report"` when HTTP 200 but body contains known APEX "no data" patterns (e.g. `"no data found"`, empty `<tbody>`, or the APEX "Page not found" shell without report fields).
6. **FR-1.6** Return `viable=True, reason=None` when HTTP 200 and body contains ASIAS content markers (report number field, `P12_AIDS_RPRT_NBR` in body, or known report table headers like `"Aircraft Make/Model"`, `"Event Date"`, `"Location"`).
7. **FR-1.7** The `fetcher` parameter accepts a `Callable[[str], Tuple[int, str]]` for unit-test injection (same pattern as NTSB).
8. **FR-1.8** Default User-Agent: `"AircraftSafetyTracker/1.0 (FAA AIDS audit)"`.

### FR-2: Global ASIAS Liveness Probe

1. **FR-2.1** Implement `probe_asias_liveness(fetcher?) → bool` in the same viability module.
2. **FR-2.2** The probe fetches the ASIAS portal landing page (`https://www.asias.faa.gov/`) or a known stable URL. Returns `True` only if HTTP status is 2xx.
3. **FR-2.3** The audit CLI **must** call `probe_asias_liveness()` before any per-record checks. If the probe returns `False`, the CLI prints an error and exits with code 2 (distinct from normal failure code 1). No `is_active` updates are written.

### FR-3: Audit CLI

**File:** `scripts/audit_faa_aids_urls.py`

1. **FR-3.1** Accept `--input PATH` (default: `data/logs/faa_aids_enrichment_final_import_01Jun2026.jsonl`) to read the list of source record IDs and URLs to check.
2. **FR-3.2** Accept `--out PATH` (default: `data/logs/faa_aids_url_audit_{YYYY-MM-DD}.jsonl`) for the classified export.
3. **FR-3.3** Accept `--concurrency N` (default: 8) to control parallel HTTP workers. Respect rate limiting — add a small random jitter between requests (50–200ms) to avoid hammering ASIAS.
4. **FR-3.4** Accept `--timeout SECONDS` (default: 30).
5. **FR-3.5** Accept `--dry-run` — run checks and write export, but do **not** update the DB.
6. **FR-3.6** Accept `--only-active` — skip rows already marked `is_active=False` in the DB (for incremental re-audit of previously-working rows only).
7. **FR-3.7** After all checks, print a summary: total checked, working count, not-working count, breakdown by reason code, and (if not `--dry-run`) count of DB rows updated.
8. **FR-3.8** Exit code 0 = success; 1 = partial failure (some URLs unreachable); 2 = ASIAS globally down (liveness probe failed, no DB changes).

### FR-4: Export JSONL Format

Each line in the export file is a JSON object with:

| Field | Description |
|-------|-------------|
| `source_record_id` | FAA AIDS C5 control number |
| `faa_aids_url` | The URL checked |
| `imported_incident_id` | `Incident.id` |
| `imported_aircraft_id` | `Incident.aircraft_id` |
| `make_model` | FAA string from `source_data.faa_aids_make_model` |
| `date` | Incident date (ISO) |
| `operator` | Operator code |
| `http_status` | HTTP status code returned (null on timeout) |
| `link_viable` | `true` / `false` |
| `link_reason` | Reason code (null when viable) |
| `bucket` | `"working"` or `"not_working"` |
| `checked_at` | ISO datetime of the check |

The **file header comment** (first two lines, starting with `#`) must state: total rows, working count, not-working count, and audit date. This matches the shape of `ntsb_enrichment_final_import_01Jun2026.jsonl`.

### FR-5: DB Write-Back

1. **FR-5.1** For each `source_record_id` classified as `not_working`: set `IncidentSource.is_active = False` where `source_name = 'FAA_AIDS'` and `source_record_id = {id}`.
2. **FR-5.2** For each `source_record_id` classified as `working`: set `IncidentSource.is_active = True` (idempotent — no-op if already True).
3. **FR-5.3** Commit in batches of 500 rows to avoid holding a long transaction.
4. **FR-5.4** After write-back, log a count of rows changed (True → False, False → True, unchanged).

3. **FR-8.3** Returns `(False, 404, "asias_record_not_found")` on HTTP 404.

## 5. Non-Goals (Out of Scope)

1. **No hard-deletes:** `IncidentSource` rows and their parent `Incident` rows are never deleted — only `is_active` toggled. This preserves import provenance.
2. **No UI redesign:** Aircraft pages already handle `is_active=False` (verify only); no new UI work.
3. **No link-check caching layer:** Each full audit re-checks all URLs; a persistent cache is a future optimization (same policy as NTSB 0006.2 §5 Non-Goal 4).
4. **No re-import of new FAA AIDS records:** Out of scope; this PRD only validates and cleans up already-imported rows.
5. **No ASIAS scraping / alternate URL resolution:** If a record is dead, it is dead. No fallback URL construction.
6. **No aircraft stat recalculation:** `Aircraft.total_incidents` counts are based on `Incident` rows, not `IncidentSource.is_active`, so counts remain unchanged. The UI simply stops showing broken links.

## 6. Design Considerations

### Failure Classification Hierarchy

```
Fetch URL
  ├─ Connection error / timeout         → asias_backend_timeout (not_working)
  ├─ HTTP 4xx                           → asias_record_not_found / http_{status} (not_working)
  ├─ HTTP 5xx or CDN error page         → asias_cdn_error / asias_backend_timeout (not_working)
  └─ HTTP 200
       ├─ Body has errors.edgesuite.net → asias_cdn_error (not_working)
       ├─ Body is APEX "no data" page   → asias_empty_report (not_working)
       └─ Body has content markers      → working
```

### Rate Limiting Strategy

ASIAS is behind Akamai CDN and may throttle bulk requests. The audit script runs as a **single terminal command** (`python scripts/audit_faa_aids_urls.py`). Concurrency is achieved internally via `concurrent.futures.ThreadPoolExecutor` (Python stdlib — no new dependencies). Progress streams live to stdout as rows are checked.

- Concurrency: 8 worker threads (configurable via `--concurrency`).
- Jitter: 50–200ms random delay between each request per worker thread.
- Redirects: followed through to final destination (FR-1.9 — if APEX redirects to a session/login page, evaluate the final landed URL for content markers).
- Retry: 1 retry on connection error only (not on 503 — that is a valid `asias_cdn_error` classification per user decision).
- Overall estimated runtime at 8 concurrency + jitter: ~15–20 minutes for 6,466 URLs.

### Export Format Alignment

The two-section structure requested by product is implemented via the `bucket` field:
```bash
# Working links
jq 'select(.bucket=="working")' data/logs/faa_aids_url_audit_2026-06-01.jsonl

# Broken links  
jq 'select(.bucket=="not_working")' data/logs/faa_aids_url_audit_2026-06-01.jsonl
```

## 9. Open Questions

1. ~~**503 = broken vs. transient?**~~ **Resolved:** No secondary guard needed. Mass 503s most likely mean incorrect URLs were scraped, not a global ASIAS outage. Per-record 503 = `asias_cdn_error` = broken.

2. ~~**APEX redirect behaviour:**~~ **Resolved:** Follow redirects all the way to the final landed URL; evaluate that page for content markers. If APEX redirects to a session/login shell, classify as `asias_empty_report`.

3. **Re-run frequency:** Should we schedule periodic re-audits (e.g. monthly)? ASIAS may restore records over time. Out of scope for this PRD but worth noting as a future enhancement.

4. **Concurrent HTTP on SQLite:** The audit script uses `ThreadPoolExecutor` for HTTP but commits DB in batches on the **main thread** after collection. HTTP worker threads return `(source_record_id, viable, status, reason)` tuples only — no DB access inside threads. This avoids SQLite threading issues entirely.

## 11. ASIAS Reliability Notes (added 2026-06-01)

### What the audit checks vs. what the spike already proved

| Question | Answered by | Result |
|----------|------------|--------|
| Does the `P12_AIDS_RPRT_NBR` URL pattern work? | PRD 0001 spike (May 23, 2026) | **YES — 100% on 500 rows + 2,500 extended sample** |
| Do all 6,466 specific records return content? | PRD 0007.1 audit (pending) | Unknown — per-record check needed |

The audit is a **hygiene check** (find deleted/empty records) rather than a format validation. Given the spike's 100% result on the same v2 DB source data, the expected not-working rate is low. The audit is not a blocker for shipping — it can be run after ASIAS recovers.

### ASIAS reliability

On 2026-06-01, the ASIAS portal (`www.asias.faa.gov`) returned Akamai CDN error pages (`errors.edgesuite.net`) for **the homepage and all record URLs** — a confirmed global backend outage visible in a standard browser. This is not an anomaly: the spike (May 23) also found that the ZIP blob download returned HTTP 500.

**Do not run the audit during an ASIAS outage.** The liveness probe (`probe_asias_liveness()`) guards against this: it requires HTTP 2xx on the ASIAS homepage before proceeding. A global outage would cause all 6,466 records to be classified `not_working`, incorrectly wiping `is_active` for the entire import.

### Is ASIAS the only source? (investigated 2026-06-01)

A full exploration of alternative FAA data sources confirmed ASIAS is the **sole public per-record URL source** for FAA AIDS data:

| Alternative | Verdict |
|-------------|---------|
| `av-info.faa.gov` Search Data | Redirects to ASIAS |
| `faa.gov/data_research/accident_incident/` | FAA **removed** AIDS data from this page (confirmed in 2022 DOT PIA) |
| `data.gov` FAA AIDS dataset | No per-record permalinks found |
| `av-info.faa.gov/data/AID/tab/*.txt` | Static bulk narrative files only (c5 + remark); no per-record links; potential alternative bulk data source |

There is no fallback URL source. If ASIAS is permanently retired, FAA AIDS per-record linking becomes impossible without a FOIA/API engagement with the FAA.
